容量与计算量的折中

MoE：让模型“参数很多”，但每个 Token 不必经过所有参数

Dense 模型里，每个 token 都会经过同一套 FFN；MoE 把 FFN 拆成多个 Experts，再由 Router 为每个 token 选择少量专家。于是 Total Parameters 可以很大，但 Activated Parameters 相对较小。

Dense每个 token 经过同一套 FFN
Router给 Experts 打 routing score
Top-K每个 token 只选少量 Experts
难点负载均衡 + All-to-All 通信

1. Dense 和 MoE 的结构差在哪

MoE 通常不是把整个 Transformer 都变成专家，而是重点把 FFN 子层稀疏化。

Dense FFN

  • Token A → 同一套 FFN
  • Token B → 同一套 FFN
  • Token C → 同一套 FFN
  • 所有 token 使用相同参数路径

MoE FFN

  • Token A → Router → Expert 1 + 3
  • Token B → Router → Expert 2 + 4
  • Token C → Router → Expert 1 + 4
  • 不同 token 走不同参数子集

3. Top-K 到底意味着什么

Router 会先给每个 Expert 一个 score，再只保留最高的 K 个。

Router Linear得到 expert logits
Routing ScoresE0=.62 E1=.08 E2=.26...
Top-K例如选 E0 + E2
Weighted Combine按 routing weight 合并输出
核心收益：总模型容量可以继续增加，但每个 token 的实际 FFN 计算只经过少量 Experts。

4. 为什么 Load Balance 是 MoE 的核心难题

如果 Router 太偏爱某几个 Expert，理论上的稀疏优势会被系统瓶颈吃掉。

热点 Expert

某个 Expert 收到过多 token，所在 GPU 变成 straggler。

冷门 Expert

大量参数很少被训练或使用，容量被浪费。

通信拥堵

Token 跨卡 dispatch / combine 变得不均匀，All-to-All 更难优化。

5. Expert Parallel：为什么 MoE 特别依赖集群网络

Experts 往往分散在不同 GPU，Router 选中谁，就要把 token 发到谁那里。

GPU 0Tokens A/B/C
Dispatch按 Router 结果重排 token
All-to-All跨 GPU 发送
Expert Compute各 GPU 上 Experts 计算
Combine再把结果送回原 token 顺序
所以 MoE 的瓶颈不只是矩阵乘法。网络带宽、通信延迟、Expert Placement、负载均衡都可能决定最终吞吐。

6. Dense vs MoE：什么时候谁更合适

MoE 不是无条件优于 Dense。

维度DenseMoE
参数使用每 token 使用同一套主要参数每 token 只激活少量 Experts
工程复杂度较低更高，需要 Router/EP/All-to-All
容量扩展参数增大通常伴随计算增大可以扩大总参数而控制激活计算
单机部署通常更友好大 MoE 更依赖集群与框架支持
主要风险计算/显存直接变大负载不均、通信、复杂调度

7. 面试怎么回答 MoE

30 秒版本先讲“为什么”，再讲“代价”。

30 秒版本

MoE 把 Transformer 的 FFN 换成多个 Experts，由 Router 为每个 token 选择少量 Top-K Experts。这样总参数量可以很大，但每 token 只激活一小部分参数，从而扩大模型容量而控制计算量。

继续追问

真正工程难点是 Router 负载均衡、Expert Parallel、All-to-All 通信，以及不同 GPU 上专家的放置和高效 kernel。

追问：MoE 参数很大，为什么推理不一定同比更慢？

因为单个 token 只经过 Router 选中的 Top-K Experts，而不是全部 Experts。需要区分 Total Parameters 和 Activated Parameters。

追问：MoE 为什么可能反而很难跑快？

虽然算术计算稀疏了，但 token 必须跨 GPU 路由；如果负载不均或网络不够快，All-to-All 和 straggler 会成为瓶颈。

MoE 不是“更多专家”这么简单：它是容量、稀疏计算和分布式通信之间的系统级折中。
