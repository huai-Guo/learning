模型结构第一关

Transformer、BERT、GPT 一次串通

Transformer 是架构骨架；BERT 是 Encoder-only；GPT 是 Decoder-only。 真正的关键不是背名字，而是理解“注意力看哪些位置、训练目标是什么、输出怎么产生”。

TransformerAttention + FFN + Residual + Norm
BERT双向 Encoder，偏表征与理解
GPT因果 Decoder，偏自回归生成
现代优化RoPE / GQA / FlashAttention

2. 一个 Decoder Block 到底长什么样

先把结构画出来，后面所有优化都能找到位置。

典型 Pre-Norm Decoder Block
Hidden States x

↓
Residual：x + Attention(x)
↓
RMSNorm
↓
FFN / SwiGLU / MoE
↓
Residual → 下一层

每一块到底负责什么？

Attention：让 token 和上下文其他 token 交换信息。


FFN：对当前位置的表示做非线性特征变换。


Residual：提供信息与梯度高速通道，深层网络更易训练。


Norm：稳定激活尺度与优化过程。

一句话：Attention 负责“去哪里取信息”，FFN 负责“拿回来后怎么加工”。

4. Q / K / V：把“找谁”和“拿什么”拆开

它们都来自同一个 X，只是经过不同可学习矩阵投影。

输入 X
↓
Q = XWq
K = XWk
V = XWv
↓
softmax(QKᵀ / √dₖ) · V

人话记忆

Q：我正在找什么。


K：我可以被怎样匹配。


V：真正会被拿走的信息。

QK 决定“关注谁”，V 决定“取回什么”。

5. 为什么要除以 √dₖ

维度越高，点积尺度容易越大，Softmax 可能过度饱和。

不缩放

  • QK 数值可能很大
  • Softmax 极尖
  • 一个位置接近 1，其余接近 0
  • 梯度变得不友好

除 √dₖ

  • 把分数尺度拉回稳定区间
  • Softmax 更平滑
  • 训练更稳定

6. 为什么要 Multi-Head

一个头只有一个匹配空间，多头让模型并行学习不同关系。

输入 X同一份 token 表示
Head 1..N不同 Q/K/V 投影空间
Concat拼接多个头结果
Output Projection映射回 hidden size
“某个头专门学语法、某个头专门学指代”只能作为直觉示意，不要把每个 head 人工固定解释成具体功能。

7. Encoder vs Decoder：根本差别是“能看哪里”

这是理解 BERT 与 GPT 的核心。

Encoder：双向

  • 当前位置能看左右两侧
  • 适合做全局表征
  • 分类 / NER / Embedding / Retrieval
  • 代表：BERT

Decoder：因果单向

  • 当前位置只能看自己和历史
  • 不能偷看未来 token
  • 天然适合自回归生成
  • 代表：GPT / Llama / Qwen
不要只说“Encoder=理解，Decoder=生成”。更准确：注意力可见范围和训练目标不同，导致它们更适配不同任务。

9. 位置编码：模型为什么知道“狗咬人”和“人咬狗”不同

Attention 自身没有天然顺序感。

Sin / Cos

原始 Transformer：给不同位置构造固定正弦/余弦编码。

RoPE

根据位置旋转 Q/K，使点积自然带上相对位置信息。现代 LLM 非常常见。

ALiBi

直接在 Attention score 上加入与距离相关的偏置。

10. MHA / MQA / GQA：核心是 KV 怎么共享

它直接关系到 KV Cache 大小和 Decode 带宽。

MHA

Q1↔K1,V1；Q2↔K2,V2……每个 Q head 都有自己的 KV。

质量稳KV 大

MQA

所有 Q heads 共用一组 K/V。

KV 最省共享最强

GQA

一组 Q heads 共用一组 K/V，在质量与 KV 成本间折中。

现代常见推理友好
为什么 GQA 对推理重要？ Decode 每步都要读取历史 KV。KV heads 越少，显存和 memory bandwidth 压力越低。

11. FlashAttention：不是新结构，而是更聪明地算同一个 Attention

高频陷阱：GQA 与 FlashAttention 不在同一层。

GQA / MQA

  • 改变模型 Attention 结构
  • 减少 KV heads
  • 降低 KV Cache

FlashAttention

  • 改变 GPU 计算与 IO 方式
  • 分块计算
  • 减少 HBM↔片上存储往返
  • 避免大中间矩阵频繁物化
不要说“FlashAttention 把 O(n²) 变成 O(n)”。经典 FlashAttention 的核心是 IO-aware exact attention。

12. Lost in the Middle：支持 1M context ≠ 中间 1M token 都利用得一样好

上下文容量和信息利用率是两回事。

开头

关键事实通常较容易被利用。

中间

在长上下文里更容易被噪声淹没。

结尾

离当前生成位置较近，通常也较容易使用。

所以实际系统会做 RAG、Rerank、Context Pruning、Summary，而不是“能塞多少就塞多少”。
