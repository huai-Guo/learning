训练生命周期总览

一个 LLM 是怎样“练出来”的

最重要的主线是：海量数据 → Pretraining → Base Model → SFT → Preference / RL → Chat / Reasoning Model。预训练负责“会语言、懂世界”，后训练负责“会按要求做事”。

2. 训练前，真正花大力气的是数据

不是“把互联网下载下来就开始训”。

清洗

HTML 噪声、模板、乱码、低质量文本、spam。

去重

减少记忆、重复训练和 benchmark 污染。

质量过滤

语言、领域、代码质量、来源与许可证。

数据配比

中文、英文、代码、数学、网页等比例会影响最终能力。

面试加分点：训练问题经常不是模型结构问题，而是数据分布、重复、污染、质量和 curriculum 问题。

4. Pretraining：最简单的目标，逼出最复杂的能力

Decoder LLM 的经典目标就是 Next Token Prediction。

训练样本其实自动就有标签
中国
↓ 预测
的
中国 的
↓ 预测
首都
中国 的 首都 是
↓ 预测
北京

为什么只猜下一个词也能学知识？

要把“爱因斯坦提出了___”补对，模型必须形成关于人物、物理和语言的内部表示；要把 Python 函数续写对，就必须学代码语法与模式。

所以能力不是显式写进程序，而是为了降低 Loss，在海量数据上被“逼着学出来”。

5. Base Model：已经很聪明，但还不一定“会当助手”

它更像极强的文本续写器。

Base Model

  • 知道很多知识
  • 能续写文本和代码
  • 可能不稳定遵循用户指令
  • 不一定遵循聊天格式

Chat / Instruct Model

  • 更稳定回答问题
  • 会遵循格式和约束
  • 具备偏好与安全行为
  • 更适合 Tool Calling / Agent

6. SFT：给它“标准答案”让它模仿

SFT = Supervised Fine-Tuning。

User：解释 TCP 三次握手
↓
Assistant：高质量标准回答
↓
继续做 Next Token Loss

SFT 主要学什么？

对话模板、instruction following、固定输出格式、领域任务、工具调用 schema、风格。

关键：SFT 仍然是监督式模仿，它擅长告诉模型“好答案长什么样”，但不天然表达“两个答案谁更好”。

7. Preference：从“模仿答案”升级到“比较答案”

这一步是理解 RLHF / DPO 的入口。

Prompt同一个问题
Answer A / B两个候选
PreferenceA > B
Optimization提高更好答案概率
偏好来源可以是人类、AI Judge、规则、测试结果或可验证 reward。

8. 经典 RLHF + PPO

先学一个“裁判”，再让模型通过强化学习争取更高 reward。

Prompt问题
Policy生成回答
Reward Model打分
PPO计算更新
Better Policy更偏向高 reward
PPO 工程复杂：Policy、Reference、Reward、Value、Rollout、Advantage 都可能参与。

9. DPO：不用把 Reward Model 放进在线训练环

直接利用 chosen / rejected 偏好对。

Chosen

模型应该提高这个回答相对概率。

Rejected

模型应该降低这个回答相对概率。

DPO 的工程吸引力：训练流程比经典 RM + PPO 简洁很多，但它仍然是在做 preference optimization。

10. GRPO：同一道题，多采样几个答案做组内比较

非常适合数学、代码等有 Verifiable Reward 的任务。

同一 Prompt
↓
Answer 1 / 2 / 3 / 4
↓
Reward：0 / 1 / 1 / 0.6
↓
组内相对优势

为什么特别适合 Reasoning？

数学最终答案、代码 unit tests 都能自动验证。模型可以大量探索，再用程序反馈强化正确轨迹。

11. Rejection Sampling：生成很多，留下好的再学

它不是 DPO/PPO 的同义词。

Generate N多样采样
Judge / Tests评分或验证
Keep Best拒掉差样本
Train Again构造下一轮训练数据
