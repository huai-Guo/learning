3 · IPv4 / IPv6 从邻居解析开始分叉

IPv4Route → ARP → 可能 NAT/PAT

先由路由表决定下一跳，再用 ARP 找当前 IPv4 邻居的 MAC。典型家庭 IPv4 出口常经过 NAPT/PAT。

IPv6Route → NDP → IPv6 Routing

IPv6 不使用 ARP，而使用 Neighbor Discovery 等机制。不能把 IPv4 的 NAT/ARP 教学链机械复制过去。

5 · TLS 与 CA 必须看成两个时间轴

网站部署前 Site → CA → Certificate

CA 验证域名控制权并签发证书。服务器提前部署证书、Intermediate 证书和对应私钥；Root CA 信任锚由 OS/Browser 预置或管理。

用户访问时 Browser ↔ Server

ClientHello / ServerHello / ECDHE / Certificate / CertificateVerify / Finished。浏览器在本地验链和验证服务器私钥持有证明，不是每次实时找 CA“批准”。

6 · 这套课程最重要的边界

DNS ≠ Port

DNS 主要给地址记录；443 通常来自 HTTPS scheme 或 URL 显式端口。

Route → ARP/NDP

先决定下一跳，再解析当前链路邻居；ARP 不是永远查默认网关。

TCP SYN 已经存在

Route、ARP、NAT、互联网路由是在运输 SYN，而不是全部做完以后才“开始 TCP”。

NAT/PAT 属于 Router

它处理已经存在的 IP/transport 报文，并维护状态映射。

两类“公钥”不要混

ECDHE 临时 key share 用于协商秘密；证书身份公钥用于验证 CertificateVerify 等身份签名。

HTTPS ≠ 永远 TCP

HTTP/1.1/2 常见主线是 TCP+TLS；HTTP/3 是 QUIC/UDP。
