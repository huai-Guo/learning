阅读原则

一个图只回答一种问题

参与者图

谁在做事？Browser、Kernel、Router、Edge、Backend 分别承担什么职责。

协议封装图

HTTP / TLS / TCP / IP / L2 是怎样的上下层关系。

时序图

谁先发什么，谁收到后再发什么；例如 TCP/TLS handshake。

状态 / 决策图

为什么走这个分支；例如同网段 vs 默认路由、LISTEN vs ESTABLISHED。

!
不要把“设备顺序”和“协议层次”混成一根箭头
“HTTP 在 TLS 上面”是协议关系；“Browser → Router → Edge”是空间路径；“ClientHello → ServerHello”是时序关系。

总母图：正确看法是“参与者 + 每段协议”，不是一条假流水线

i
重要：TCP / TLS / HTTP 不是“在 Edge 之前做完一次，然后 CDN/WAF/LB 才开始”
Edge / LB / Gateway 本身就是这些连接和协议的参与者。一次业务请求往往会在多个代理边界上结束一条连接，再建立下一条连接。
