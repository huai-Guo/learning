Phase 5

HTTP / HTTPS / TLS

从 HTTP 请求语义一路讲到 TLS 1.3、证书链、ECDHE、CertificateVerify、Finished 和 Session Resumption。重点不是背消息名，而是搞清楚：谁在证明谁、哪把钥匙干什么、哪个阶段开始加密。

一句话：HTTP 负责业务语义；TLS 负责身份、机密性和完整性；TCP 负责可靠有序地搬运 TLS 字节。

1 · 三层职责

HTTP

业务语义

Method、Path、Header、Body、Status、Cache、Cookie、认证相关字段。

TLS

安全通道

身份认证、密钥建立、机密性、完整性、握手完整性和会话恢复。

TCP

可靠字节流

负责把 TLS 产生的字节可靠、有序送达，不理解 HTTP 业务语义。

6 · HTTPS 为什么存在

Confidentiality

看不懂

旁观者不能直接读取 HTTP 内容。

Integrity

改不了

被篡改的受保护数据能够被检测出来。

Authentication

冒充不了

Browser 能验证当前 Server 是否持有目标 hostname 对应可信身份私钥。

7 · 四种密码学能力

Symmetric

高效保护大量数据，例如 AES-GCM、ChaCha20-Poly1305。

Public-key

Private/Public Key 体系，用于签名、身份认证等。

Hash

单向摘要，不是加密，也没有“解密 Hash”。

Signature

Private Key 签名、Public Key 验证，不是“私钥加密、公钥解密”。

8 · TLS 中两类“公钥”

Key Establishment

ECDHE Ephemeral Key Share

Client 和 Server 每次连接生成临时密钥材料，用于得到 Shared Secret。

Identity

Certificate Public Key

用来验证 Server 对当前 Handshake Transcript 的 CertificateVerify 签名。

9 · CA 有两条时间线

网站部署前

CA 签证书

Site 申请证书，CA 验证控制权并签发，Server 提前部署 Certificate、Intermediate 和 Private Key。

用户访问时

Browser ↔ Server

Server 发证书链，Browser 本地验链、验 hostname、验 CertificateVerify；不是每次实时问 CA 是否批准。

11 · Certificate Signature 与 CertificateVerify

Certificate Signature

CA Private Key 签 Server Certificate，表示 CA 对证书中的身份与 Public Key 做背书。

CertificateVerify

Server 用证书对应 Private Key 签当前 TLS Handshake Transcript，证明当前握手方真的持有 Private Key。

13 · Finished 和 CertificateVerify 不是一个作用

CertificateVerify

证明当前 Server 持有证书对应 Private Key，属于身份绑定。

Finished

证明双方对 Handshake Transcript 和 Key Schedule 理解一致，握手未被悄悄篡改。

14 · TLS 1.3 Cipher Suite 到底描述什么？

TLS 1.3 的 Cipher Suite 主要描述 AEAD + Hash，例如 TLS_AES_128_GCM_SHA256。ECDHE Group 和 Signature Algorithm 在其他协商中选择，不再像 TLS 1.2 那样全部塞进一个超长名字。

15 · Session Resumption 与 0-RTT

Resumption

PSK / Ticket

复用之前安全会话派生出的恢复状态，减少完整证书握手的网络和计算成本。

0-RTT

Early Data

可以更早发送应用数据，但存在 Replay 风险。不能把不可安全重放的业务操作随意放进 0-RTT。

16 · HTTPS 加密什么，没加密什么？

通常被 TLS 保护

HTTP Method、Path、Headers、Cookie、Authorization、Body、Response Body。

仍需暴露/可推断的网络信息

IP、packet size、timing、TCP/UDP metadata；经典 TLS 中 SNI 也可能可见，传统 DNS 也可能泄露 hostname。

17 · TLS 认证服务器，不等于认证用户

TLS Server Authentication

当前 Server 是否持有 shop.example.com 对应可信 Certificate Private Key？

Application Authentication

当前用户是谁？通常由 Cookie、Session、Bearer Token、OAuth 等业务机制解决。

18 · 记忆模型

HTTP → 业务语义 TLS → Certificate Chain → CertificateVerify → (EC)DHE / PSK → HKDF → AEAD Traffic Keys TCP → 可靠有序字节流 最关键： ECDHE Ephemeral Key ≠ Certificate Identity Key Certificate Signature ≠ CertificateVerify CA 签发时间线 ≠ 用户握手时间线
