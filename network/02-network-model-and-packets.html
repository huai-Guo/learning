Chapter 02 · From Process to NIC

网络分层、封装与 OS 收发包：
数据到底怎么从进程走到网卡？

这一章把“协议分层”从抽象名词变成真实执行路径：用户态程序 → Socket → TCP → IP → Route → Neighbor → qdisc → Driver → DMA → NIC，再反方向走回应用。

这一章重点

  • 分清“协议层、封装层、本机实现路径、空间路径”四种不同图。
  • 理解 send() 不是“立刻把数据扔到网线”。
  • 理解 MTU、MSS、GSO/TSO/GRO 与抓包差异。

最终你应该能说清

  • fd、Socket Object、TCP Connection 的关系。
  • Kernel 如何根据四元组把收到的数据交给正确 Socket。
  • 为什么网卡、驱动、DMA、Ring Buffer 都会出现在网络课里。

!
最常见误区
“HTTP 在 TLS 上面”是协议分层；“Browser 在 Kernel 上面”是实现路径；“Laptop 到 Router”是空间路径。它们不是同一个维度。
分层模型

2. TCP/IP 四层与 OSI 七层：核心不是背层数，而是理解职责边界

TCP/IP 视角
Application HTTP / TLS / DNS / RPC ↓ Transport TCP / UDP / QUIC* ↓ Internet IP / ICMP ↓ Link Ethernet / Wi-Fi

工程中更常直接按 TCP/IP 体系讨论。QUIC 的实现位置特殊，但承担大量 Transport 职责。

OSI 视角
7 Application 6 Presentation 5 Session 4 Transport 3 Network 2 Data Link 1 Physical

OSI 更适合作为“职责分类模型”。现实协议不会总严格一一落在某一层。

i
为什么要分层？
因为每层只承诺自己的接口与语义。应用不需要知道网卡 DMA 细节，Router 也不需要理解你的 JSON 业务字段。

数据大小边界

4. MSS 与 MTU：为什么不能“无限大一个包发出去”

MTU

限制当前链路承载的 IP Packet 大小

例如 Ethernet 常见 MTU 1500。它不是 TCP 独有概念。

MSS

限制 TCP Payload 大小

典型 IPv4 情况可近似理解为 MTU - IP Header - TCP Header，因此常见约 1460 字节。

应用数据 ↓ TCP 依据 MSS 切分 ↓ TCP Segment ↓ IP Header ↓ IP Packet ≤ Path / Link MTU ↓ L2 Frame
!
为什么更希望 TCP 分段，而不是依赖 IP Fragmentation？
因为 Fragmentation 增加中间网络复杂度与丢片风险，现代网络更倾向通过 MSS / PMTU Discovery 在发送端控制合适大小。
内核网络层

5. Route / Neighbor / Link：知道目标 IP 后还没结束

Route

目标 IP → 出接口 / 下一跳

Kernel 查路由表，做最长前缀匹配，决定从哪张网卡、往哪个 next hop 发送。

Neighbor

下一跳 IP → 链路地址

IPv4 Ethernet 常用 ARP；IPv6 使用 NDP。

Link

构造当前一跳 Frame

这一层目标 MAC 只对当前链路有效；跨 Router 后会重新构造下一跳 L2 Header。

TCP Segment ↓ IP Packet ↓ Route Lookup ↓ Next Hop ↓ ARP / NDP ↓ L2 Header ↓ Frame

DMA

让 NIC 与内存之间搬运数据时尽量减少 CPU 逐字节复制负担。Driver 负责设置 Descriptor，NIC 直接读写内存区域。

性能优化

7. 为什么抓包里看到的“包大小”有时和线上不一样？

GSO

Generic Segmentation Offload

Kernel 先用较大的逻辑 Packet 表示数据，晚一些再拆分。

TSO

TCP Segmentation Offload

部分 TCP 分段工作交给 NIC 完成，减轻 CPU 处理负担。

GRO

Generic Receive Offload

接收方向把多个 Packet 合并成较大单元再交给上层，减少协议栈处理次数。

i
抓包位置决定你看到什么
如果抓包点在 offload 前后不同位置，你看到的 Packet 边界和大小就可能不同。不要机械把抓包软件里的一行等同于“线缆上真实一帧”。

为什么不用每包一个硬中断？

高 PPS 下频繁硬中断成本很高。Linux 常通过 NAPI 在“中断通知 + 批量轮询”之间折中处理。

为什么能找到正确 Socket？

Kernel 根据协议、local/remote IP/port 和 TCP state 等信息做 demultiplexing，把数据送到对应 Socket receive buffer。

9. 一页总结：从 send() 到 NIC，再从 NIC 回到应用

【发送】 Application ↓ send() Syscall ↓ Socket Send Buffer ↓ TCP ↓ IP ↓ Route ↓ Neighbor ↓ L2 ↓ qdisc ↓ Driver ↓ TX Ring / DMA ↓ NIC ↓ Network 【接收】 Network ↓ NIC ↓ RX Ring / DMA ↓ Driver / NAPI ↓ L2 ↓ IP ↓ TCP ↓ Socket Demux ↓ Receive Buffer ↓ Application

这一章最该记住

  1. send() 是把数据交给内核，不等于立即上网。
  2. MSS 控 TCP payload，MTU 控链路/IP Packet 尺寸边界。
  3. Route 找下一跳，Neighbor 找当前链路地址。
  4. qdisc、Driver、DMA、Ring 都是实现路径，不是协议层。
  5. 接收方向需要根据连接状态把 Packet demux 到正确 Socket。
