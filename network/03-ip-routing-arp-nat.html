Phase 3

IP、CIDR、Route、ARP/NDP、ICMP、NAT

这一章把“目标 IP 已经知道”之后的世界讲透：如何判断同网段、如何选下一跳、为什么先 Route 再 ARP/NDP、路由器如何逐跳转发，以及 NAT/PAT 为什么必须放在路由器边界里。

一句话母线：IP 负责最终目标，Route 负责下一跳，ARP/NDP 负责当前链路邻居，Router 逐跳转发，NAT/PAT 可能在边界上改写地址与端口。

1 · CIDR：为什么 192.168.1.20/24 属于 192.168.1.0/24？

IP

192.168.1.20

32 位 IPv4 地址，人类用点分十进制阅读。

Prefix

/24

前 24 位属于网络前缀，剩余 8 位属于主机/interface 部分。

Network

192.168.1.0/24

IP 与 /24 mask 做 AND 后得到网络前缀。

2 · Route 先回答“下一跳是谁”

同网段

192.168.1.20 → 192.168.1.50

Route 判断目标在本地直连网络，next hop 就是 192.168.1.50 自己，然后 ARP 目标主机。

异网段

192.168.1.20 → 203.0.113.20

找不到更具体直连路由，使用 default route，next hop = 192.168.1.1，再 ARP 网关。

3 · 最长前缀匹配

Route目标 10.1.2.99 是否匹配结果
10.0.0.0/8是候选
10.1.0.0/16是候选
10.1.2.0/24是最终选择
0.0.0.0/0是兜底

4 · Route → ARP，而不是“ARP 永远找网关”

dst IP = 203.0.113.20
↓
Route Lookup
↓
next hop = 192.168.1.1
↓
ARP / Neighbor Cache
↓
192.168.1.1 → Router MAC
↓
构造当前链路 L2 Frame

5 · 为什么 dst MAC 和 dst IP 可以不是同一个设备？

Ethernet: src MAC = Laptop MAC dst MAC = Router MAC IP: src IP = 192.168.1.20 dst IP = 203.0.113.20 解释： MAC 只负责当前一跳； IP 指向最终目标。

6 · Router 每一跳到底做什么？

1. 收到当前链路 Frame

检查并处理当前 L2 封装。

2. 看 IP dst

真正的远端目标仍然写在 IP Header 里。

3. 查 FIB

根据最长前缀匹配选下一跳和出接口。

4. 重建下一跳 L2

MAC/L2 Header 随链路变化，再继续转发。

7 · Control Plane 与 Data Plane

Control Plane

形成“地图”

BGP、OSPF、IS-IS、静态路由等帮助设备学习“哪些前缀从哪里可达”。

Data Plane

真正“开车”

每个包到来时高速查 FIB/forwarding table，决定下一跳并转发。

8 · IPv4 ARP 与 IPv6 NDP

IPv4

ARP

ARP Request 常见广播，ARP Reply 常见单播。OS 会维护邻居缓存，不需要每包都广播。

IPv6

NDP

Neighbor Solicitation / Advertisement 基于 ICMPv6，并使用 multicast 等机制，不使用 ARP。

9 · ICMP、ping、traceroute

ICMP

承担网络层差错/控制/诊断信息，例如 Time Exceeded、Echo 等。

ping

经典 IPv4 使用 Echo Request / Echo Reply。ping 不通不能直接推出 TCP/HTTPS 不通。

traceroute

逐步增加 TTL/Hop Limit，利用中间路由器返回 Time Exceeded 来推断路径节点。

10 · NAT/PAT 的正确位置

Laptop 已产生 TCP/IP packet
↓
Route + ARP → 发到 Home Router
↓
Router: conntrack / NAT policy
↓
192.168.1.20:53124 ↔ 198.51.100.8:62001
↓
WAN / Internet forwarding

11 · SNAT / DNAT / PAT

SNAT

改 source

常见于内网出公网：192.168.1.20 → 198.51.100.8。

DNAT

改 destination

例如公网 8443 转发到内部 192.168.1.100:443。

PAT/NAPT

端口参与映射

大量内部连接共享较少公网 IPv4 时，用地址+端口维护可区分映射。

12 · 返回包为什么能回到原来的电脑？

Server reply: 203.0.113.20:443 → 198.51.100.8:62001 Home Router: 查 conntrack / NAT state ↓ reverse translation ↓ 192.168.1.20:53124 Laptop: TCP socket lookup ↓ Browser

13 · NAT ≠ Firewall

NAT

地址/端口改写与映射。

Firewall

根据安全/策略规则允许、拒绝或处理流量。家庭路由器常把两者放在同一个盒子里，所以容易混淆。

14 · CGNAT 与 IPv6

CGNAT

家庭路由器外面可能还有一层 NAT

你的 WAN 地址可能还是共享地址，运营商再把很多用户映射到公网 IPv4。

IPv6

通常不依赖 NAPT 解决地址不足

但仍然需要 routing 和 firewall；“没有 NAT”不等于“没有安全边界”。

15 · 记忆模型

IP：最终目标是谁。
Route：下一跳走谁。
ARP/NDP：当前链路怎么找到下一跳。
Router：逐跳查 FIB 并继续转发。
NAT/PAT：某些边界上改写地址/端口，并保存状态让返回流量能反向映射。
