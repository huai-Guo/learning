Chapter 03 · IP & Routing

IP、CIDR、Route、ARP/NDP、ICMP、NAT：
一个 IP Packet 为什么真的能找到另一台机器？

这一章把“互联网转发”拆成几件不同的事情：IP 定义地址，CIDR 定义前缀，Route 决定下一跳，ARP/NDP 找当前链路目标，Router 逐跳转发，NAT/PAT 在边界改写 endpoint。

先建立正确顺序

  • Route 决定下一跳，不是 ARP 决定。
  • ARP 只在当前 IPv4 链路上找下一跳 MAC。
  • Internet Router 不知道“整个终点路径”，只知道下一跳。

这一章最容易混的概念

  • NAT ≠ Routing ≠ Firewall。
  • Switch MAC Table ≠ Router Route Table。
  • BGP 控制面 ≠ 每个数据包的实际转发动作。

地址与前缀

1. IP / CIDR：192.168.1.20/24 到底在说什么？

IPv4
192.168.1.20 = 32 bit address /24 = 前 24 bit 是 network prefix = 后 8 bit 是 host part

IP 更准确地说是配置在网络接口上的地址，不是“电脑天生只有一个 IP”。

CIDR
/24 → 2^(32-24) = 256 addresses /25 → 128 /26 → 64 /30 → 4

前缀越长，网络块越小；前缀越短，能覆盖的地址范围越大。

下一跳判断

2. 同网段与异网段：决定“下一跳是谁”

同网段
本机：192.168.1.20/24 目标：192.168.1.50 Route 判断： 192.168.1.50 属于直连网段 下一跳： 就是 192.168.1.50 本身

接下来 ARP 查询目标主机自己的 MAC。

异网段
本机：192.168.1.20/24 目标：203.0.113.20 目标不在直连网段 ↓ 匹配默认路由 ↓ next hop = 192.168.1.1

这时 ARP 找的是默认网关 MAC，不是最终 Server MAC。

Route 决策

3. Route Table：目标 IP 到底应该从哪里发？

Destination Next Hop Interface 192.168.1.0/24 direct Wi-Fi 10.0.0.0/8 192.168.1.254 Wi-Fi 0.0.0.0/0 192.168.1.1 Wi-Fi
Longest Prefix Match

如果 /24、/16、/0 都能匹配，优先选择最具体、前缀最长的规则。

Default Route

0.0.0.0/0 匹配所有 IPv4，是“其他规则都不匹配时”的兜底。

Next Hop

主机不需要知道完整 Internet 路径，只要知道把 Packet 交给谁即可。

!
主机不会提前算出整条互联网路径
每个 Router 都根据自己的 FIB 做一次局部下一跳决策。Internet 本质上是“逐跳推进”。
控制面与数据面

4. BGP、FIB、TTL：谁负责“学路”，谁负责“转包”？

Control Plane

谁负责形成路由信息？

BGP 等协议负责在自治系统之间传播前缀可达性，帮助路由设备形成路由选择。

Data Plane

一个真实 Packet 到来时怎么办？

Read dst IP ↓ Lookup FIB ↓ Choose next hop / interface ↓ Forward packet
TTL / Hop Limit

每经过 Router 减少，归零时丢弃，防止错误路由让 Packet 永远绕圈。

为什么 traceroute 能看到每一跳

它利用不同 TTL / Hop Limit 触发中间 Router 的 ICMP 超时反馈，逐步显露路径。

当前链路

5. ARP / NDP / Switch：IP 知道下一跳，还要知道链路地址

ARP
“谁是 192.168.1.1？” 192.168.1.1 → AA:BB:CC:DD:EE:FF

ARP 解决 IPv4 下一跳 IP → MAC。它不是跨互联网查最终服务器 MAC。

NDP

IPv6 不使用 ARP，而是使用 Neighbor Discovery Protocol 完成邻居发现、地址解析等相关功能。

Switch MAC Table

Switch 根据 MAC Table 决定 Frame 往哪个端口发；Router 根据 Route/FIB 决定 IP Packet 下一跳。两者不是同一个表。

第一跳 Frame： src MAC = Laptop MAC dst MAC = Router LAN MAC 里面的 IP Packet： src IP = 192.168.1.20 dst IP = 203.0.113.20 跨 Router 后： L2 Header 会换 IP 目标通常仍然是最终 Server （若发生 NAT 则地址可能被改写）
反馈协议

6. ICMP、ping、traceroute：它们到底分别在测什么？

ICMP

为 IP 世界提供错误与诊断反馈，比如 Echo、TTL exceeded、Destination Unreachable 等。

ping

通常通过 ICMP Echo Request / Reply 测试某种 IP 可达性与 RTT，不代表 TCP/HTTPS 一定可用。

traceroute / tracert

通过 TTL/Hop Limit 逐步变化，观察中间跳点的反馈。

!
ping、traceroute、curl 测的不是一件事
ping 偏 ICMP 可达性；traceroute 看路径；curl 进一步触及 TCP/TLS/HTTP。一个成功不能代替另一个成功。
边界地址转换

7. NAT / PAT：边界设备如何让私网连接共享公网 IPv4？

Inside: 192.168.1.20:53124 → 203.0.113.20:443 ↓ NAT/PAT mapping Outside: 198.51.100.8:62001 → 203.0.113.20:443
顺序纠错

不要机械画成“先 NAT 再 PAT”。典型 NAPT/PAT 中，地址和端口改写常是同一次状态映射的一部分。

为什么返回包能回来

NAT 设备维护 Conntrack / Mapping State，把公网 endpoint 再映射回内部 endpoint。

i
NAT ≠ Routing ≠ Firewall
Routing 负责下一跳；NAT 负责地址/端口改写；Firewall 负责允许/拒绝流量。实际设备可以同时做三件事，但概念上必须分开。
NAT 家族

8. SNAT、DNAT、PAT、CGNAT 分别是什么？

SNAT

改 Source Address，常用于内网出网时把私网源地址转换成公网地址。

DNAT

改 Destination Address，常用于把公网入口流量转发到内部服务。

PAT / NAPT

同时利用 Port 维度区分多个连接，让多个内部 endpoint 共享有限公网 IP。

CGNAT

运营商级 NAT。你家 Router 的 WAN IPv4 甚至可能还是私网/共享地址。

为什么公网直连家里服务麻烦

NAT/CGNAT 默认只认识已有映射。外部主动新建连接时，没有对应内部目标就无法直接送达。

IPv6

IPv6 地址空间巨大，通常不依赖 IPv4 那样的 NAPT 才能让主机拥有可路由地址，但 Firewall 仍然非常重要。

9. 一页总结：一个 IPv4 Packet 的出站与返回

【出站】 Application / TCP ↓ IP Packet ↓ Route Table / Longest Prefix Match ↓ Next Hop ↓ ARP ↓ L2 Frame ↓ Home Router ↓ NAT/PAT Mapping ↓ ISP / Internet Routers ↓ FIB lookup hop by hop ↓ Target Network 【返回】 Server Response ↓ Internet ↓ Public NAT endpoint ↓ Conntrack / Mapping ↓ Private endpoint ↓ Client Kernel / Socket

这一章最该记住

  1. CIDR 定义前缀范围。
  2. Route 先决定下一跳。
  3. ARP/NDP 只解决当前链路邻居。
  4. BGP 影响路由信息，FIB 才负责真实 Packet 转发。
  5. NAT/PAT 是状态化 endpoint 改写，不是 Routing。
